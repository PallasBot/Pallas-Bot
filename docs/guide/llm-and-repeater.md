# `@牛牛` 与复读

分清两条回复路径：日常接话优先本机语料；明确 `@牛牛` 才走 LLM 对话（Bot Provider）。默认策略是语料作底，AI 作教练，而不是把整群聊天交给通用大模型。

## 两条路径

| 路径 | 触发条件 | 行为 |
| --- | --- | --- |
| 复读 / 接话 | 日常群聊自动 | 优先本机语料；少数「强场景」可让 AI 选句 / 轻润色 |
| `@牛牛` LLM 对话 | 明确 @ 牛 | 走 LLM 对话（仍带牛格与群味） |

LLM 对话与接话中的 AI 介入都走 **Bot Provider**（控制台 **AI 配置**）。**AI Runtime** 只用于唱歌 / TTS 等媒体与遗留 RWKV，与本页LLM 对话路径无关。

## 复读 / 接话

- 日常群聊自动触发，优先本机学到的语料。
- 受牛格、群风格、单群表达参考影响。
- **多数时候不走 AI**；只有机会合适时才会尝试。

### 强场景与弱场景

系统会把接话机会分成两档（内部名 `scene_tier`）：

| 档位 | 大致何时出现 | AI 怎么参与 |
| --- | --- | --- |
| 强场景 | 有人 @、明显接话 cue 且有候选语料、或刚来回过几句且有语料池 | 过门控后按比例尝试 AI（默认约一半），失败仍发原语料 |
| 弱场景 | 其余日常接话 | 继续语料底盘；AI 介入更克制 |

强场景管线大致是：**选句 →（必要时）润色 → 轻顺口气**；任一步失败就回落语料，不会硬编一句「像机器人」的话顶上去。

接话积极程度、强场景冷却 / 尝试比例等可在控制台调整；详见 [复读插件](/plugins/repeater)。

## `@牛牛` LLM 对话

1. 在控制台 **AI 配置** 配好 Bot Provider 并测通。
2. 打开总闸 **`LLM_CHAT_ENABLED`**（**AI 配置 → 对话**）。
3. 在群里明确 `@牛牛` 试一句。

比日常接话更自由：可带会话、记忆等能力；同样会吃到牛格、情感与本群 **表达参考**。详见 [智能对话（llm_chat）](/plugins/llm_chat) 与 [AI 扩展](ai.md)。

## 反哺与表达库

AI **成功发出**之后，还可能：

| 机制 | 作用 |
| --- | --- |
| 反哺写回 | 把合适的答句收进接话语料审批 / 晋升（强场景更优先进入可写回） |
| 单群表达库 | 记住「什么场合常说什么」；之后注入 `@` 与强场景提示，不跨群共享 |

因此偶发「说法变了 / 语料变多」往往是闭环在学，不一定是故障。相关开关在控制台 **AI 配置**（如收集反哺、表达注入 / 学习）。

## 配置 `LLM_REPEATER_MODE`

控制**接话**是否使用 AI（不影响 `@` LLM 对话总闸）。总闸 **`LLM_CHAT_ENABLED`** 关闭时，下表均不生效。

| 值 | 效果 |
| --- | --- |
| `off` | 纯语料接话，AI 不介入 |
| `select` | 命中语料时 AI 选句 |
| `select_polish_lite` | 选句为主，少数回复轻润色（默认） |
| `select_fallback` | 选句；语料缺失时才现编 |
| `fallback` | 仅语料缺失时 AI 现编 |
| `polish` / `both` | 遗留：以润色 / 补位为主（仍可用） |

总闸与装法 → [AI 扩展](ai.md)。

## 成功信号

- 未开 `LLM_CHAT_ENABLED` 时，日常接话仍可走语料。
- 打开总闸并 Provider 测通后，`@牛牛` 能收到LLM 对话回复；接话按 `LLM_REPEATER_MODE` 行为符合预期。
